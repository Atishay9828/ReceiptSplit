# M007.5 Architecture Hardening Report

This report summarizes the findings and fixes for the critical and high issues identified during the Phase 1 Architecture Validation phase.

## Critical Findings

### C-1: SQL injection in cas_update
**Finding**: The custom `cas_update` logic might be vulnerable to SQL injection if not properly parameterized.
**Fix**: Addressed in previous commits.

### C-2: transaction ownership (Resolved)
**Hypothesis**: Does `async with db.begin()` in service methods correctly persist data in a production-style request lifecycle?
**Finding**: Originally, the architecture suffered from a transaction layering bug. Implicit transactions opened by auth dependencies caused `db.begin()` in service methods to throw `InvalidRequestError: A transaction is already begun`.
**Fix**: We revised the transaction architecture. The database session dependency (`get_db()`) now owns the outer request transaction lifecycle, handling top-level commits/rollbacks. Service methods use nested transactions (`async with db.begin_nested():`) to isolate business logic while allowing the outer commit to finalize changes. This guarantees atomicity across auth dependencies, domain logic, and outbox event publishing, and prevents `InvalidRequestError`. Verified by `test_c2_transaction_persistence.py`.

### C-3: claim race (Resolved - False Positive)
**Hypothesis**: Two concurrent requests claiming the same item might both read `already_claimed=0`, pass validation, and over-allocate the item.
**Finding**: The claim operation is protected by a CAS (Compare-And-Swap) version check on the parent line item row. Concurrency testing confirmed that if multiple clients attempt to claim concurrently using the same initial item version, only one CAS update succeeds. The others fail with `VersionConflict` and must retry. 
**Fix**: No code changes needed. Added rigorous concurrent integration tests in `test_c3_claim_race.py`.

## High Findings

### H-2: auth rollback behavior
**Finding**: Auth dependencies and unhandled errors could leave transactions unmanaged.
**Fix**: Implicit transactions from auth dependencies are now explicitly closed via `await db.rollback()`.

### H-4: rate limiter memory / multi-process issue
**Finding**: Addressed in previous commits.

### H-5: SignedPaise inconsistency
**Finding**: Addressed in previous commits.

## Additional Fixes Made During Hardening
- **Router Cleanup**: Removed unnecessary router rollback calls.
- **Room Status Bypass**: Fixed logic in `update_room` that allowed state-machine bypasses when mixing `status` with standard fields.
- **ETag Support Restoration**: Restored API-4 `ETag` generation and caching support in the `preview_split` endpoint. Calculates preview and version in a single transaction.

## Conclusion
Phase M007.5 is fully complete. The system's transaction management and concurrency controls are robustly proven against real Testcontainers PostgreSQL databases. The architectural foundations are secure for the next phase.
